# Community Participation and Notifications

This repository welcomes independent evidence, alternative explanations and attempts to falsify current hypotheses.

## Where to participate

- **Issues** are for structured, evidence-bearing independent reproductions. Use the `Independent reproduction` issue form.
- **Discussions** are for questions, related experiences, hypotheses, interpretation of evidence and proposals that do not yet meet the issue evidence gate.
- **Private vendor/support channels** are for account-specific or correlation material that should not be public.

A discussion, reaction, vote or `same here` comment can help discover patterns, but it is not automatically an independent technical reproduction.

## Before posting

Do not publish credentials, cookies, tokens, authorization headers, account/user IDs, conversation/project/channel IDs, request/correlation IDs, IP addresses, email addresses, precise locations, private support correspondence, unrelated conversation content, local usernames or filesystem paths.

Do not intentionally generate repeated failures, automate retries, bypass rate limits or create load to obtain evidence. Respect `Retry-After` and other authoritative backoff signals.

## Following the investigation

GitHub participants can use the repository's **Watch** control to choose the notification level that fits them. Contributors should also verify their own GitHub notification delivery preferences if they want repository activity delivered by email or another configured channel.

Notification preferences are account-specific: this repository cannot force email delivery for another user, and public participation should not require publishing an email address.

## Evidence standard

Please separate:

- direct observations;
- independent reproductions;
- external reports;
- inferences;
- hypotheses;
- facts that remain not determined.

The current investigation does **not** claim that every conversation-loading failure has one cause, that HTTP 429 is the universal mechanism, or that a global outage/overload has been demonstrated.
