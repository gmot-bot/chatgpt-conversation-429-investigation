# GitHub in 60 Seconds — for Non-Technical Visitors

You do not need to learn Git or programming.

## Read help

**Tap/click:** `README` -> **Community Help** -> choose your symptom.

## Ask the community

**Tap/click:** `Discussions` -> open the closest existing topic -> `Comment` / `Reply`.

Use ordinary language. Example: “My old conversation is visible in search, but it will not open. I see Too many requests.”

## Ask a new question

If no existing Discussion fits: `Discussions` -> `New discussion` -> choose the closest category -> write what you see -> remove private information -> publish.

## Report a structured observation

`Issues` -> `New issue` -> choose **Community help question** or **Simple problem report** -> complete the short form.

## Found an answer?

In a Q&A Discussion, an accepted answer can be highlighted so later visitors find it quickly. If a response solved or clarified your question, mark it as the answer when GitHub offers that option.

## Never paste

Passwords | tokens | cookies | email addresses | account IDs | conversation IDs | request IDs | IP addresses | precise location | private chat text | raw HAR files.
